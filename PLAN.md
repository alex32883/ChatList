# План реализации программы Chatlist

## Этап 1: Подготовка проекта и структуры

1.1. Создать структуру проекта:
- `main.py` - основной файл с GUI
- `db.py` - модуль для работы с базой данных
- `model.py` - логика работы с моделями
- `network.py` - отправка запросов к API
- `config.py` - загрузка конфигурации из .env
- `requirements.txt` - зависимости проекта
- `.env.example` - пример файла с переменными окружения

1.2. Установить зависимости:
- PyQt5 для GUI
- requests/httpx для HTTP-запросов
- python-dotenv для работы с .env
- sqlite3 (встроенная библиотека)

## Этап 2: Проектирование и создание базы данных

2.1. Создать модуль `db.py` с функциями:
- `init_database()` - инициализация БД и создание таблиц
- Функции для работы с таблицей `prompts` (CRUD)
- Функции для работы с таблицей `models` (CRUD)
- Функции для работы с таблицей `results` (CRUD)
- Функции для работы с таблицей `settings` (CRUD)

2.2. Реализовать создание всех таблиц при первом запуске

## Этап 3: Модуль конфигурации и работы с API

3.1. Создать `config.py`:
- Загрузка переменных окружения из .env
- Хранение API-ключей для разных моделей
- Настройки по умолчанию

3.2. Создать `network.py`:
- Функция отправки запроса к OpenAI API
- Функция отправки запроса к Groq API
- Универсальная функция для отправки запросов к разным API
- Обработка ошибок и таймаутов

## Этап 4: Модуль работы с моделями

4.1. Создать `model.py`:
- Класс или функции для работы с моделями из БД
- Получение списка активных моделей
- Валидация настроек моделей
- Формирование запросов для разных типов API

## Этап 5: Основной интерфейс (GUI)

5.1. Создать главное окно в `main.py`:
- Область ввода промта (текстовое поле)
- Выпадающий список для выбора сохраненных промтов
- Кнопка "Отправить запрос"
- Таблица результатов (QTableWidget) с колонками:
  - Название модели
  - Текст ответа
  - Checkbox "Selected"
- Кнопка "Сохранить выбранные"
- Кнопка "Новый запрос"

5.2. Реализовать временную таблицу результатов в памяти:
- Структура данных для хранения результатов (список словарей)
- Обновление GUI при получении новых результатов

5.3. Реализовать асинхронную отправку запросов:
- Использование потоков или async/await для параллельных запросов
- Индикатор загрузки во время отправки запросов
- Обновление таблицы по мере получения ответов

## Этап 6: Функционал сохранения промтов

6.1. Добавить интерфейс для работы с промтами:
- Кнопка "Сохранить промт"
- Поле для ввода тегов при сохранении
- Выпадающий список с историей промтов
- При выборе промта из списка - загрузить его в поле ввода

6.2. Реализовать сохранение промта в БД с датой и тегами

## Этап 7: Сохранение результатов в БД

7.1. Реализовать логику сохранения:
- При нажатии "Сохранить выбранные":
  - Получить все строки с selected = True
  - Сохранить каждую в таблицу results с привязкой к промту
  - Очистить временную таблицу
  - Обновить интерфейс

## Этап 8: Управление моделями (опционально, но желательно)
